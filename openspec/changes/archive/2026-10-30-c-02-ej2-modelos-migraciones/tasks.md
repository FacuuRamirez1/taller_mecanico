# Tasks

> **Strict TDD en forma de verificación** (igual que C-00/C-01): no hay pytest; la aceptación son comandos de CLI y consultas a la base. En cada task se corre **primero** la verificación y se registra que da rojo (RED), luego se escribe el código mínimo hasta que da verde (GREEN) y se corre una segunda verificación con otra entrada (TRIANGULATE).
>
> **Convenciones**: todo se corre desde la raíz del repo con el venv activo (`source .venv/Scripts/activate`), nunca con el cwd dentro de `openspec/changes/*`. **Nunca** se abre, imprime ni edita el `.env`; ninguna contraseña va en la línea de comandos. `<PORT>` = el `POSTGRES_PORT` de tu `.env` (5433 en la máquina del proponente). Para no ensuciar la salida, anteponer `SQL_ECHO=false` a los comandos de Python que tocan la base.
>
> **Ayudantes** (se pegan en la terminal; no se versionan):
> - **[M] metadata de una tabla** (sin base): `python - <<'EOF'` → `from <módulo> import <Clase> as T; t=T.__table__; print(t.name); [print(c.name, repr(c.type), c.nullable, c.server_default is not None) for c in t.c]; print(sorted(str(k.name) for k in t.constraints if type(k).__name__ in ('CheckConstraint','UniqueConstraint'))); print(sorted((str(i.name), i.unique, str(i.dialect_options['postgresql'].get('where'))) for i in t.indexes))` → `EOF`.
> - **[Q] consulta** (con base, vía `Settings`): heredoc que hace `e=crear_engine(Settings())`, `async with e.connect() as c: for f in (await c.execute(text(SQL))).all(): print(*f)` y `await e.dispose()`.
> - **[T] intentos en transacción descartable**: heredoc con una lista `PASOS` de sentencias SQL; abre `c.begin()`, corre cada paso dentro de `c.begin_nested()` e imprime `OK <sql>` o `FALLA <sqlstate> <constraint_name> <primera línea del mensaje> <sql>` (sqlstate/`constraint_name` desde `x.orig` y `x.orig.__cause__`), y al final hace **`ROLLBACK`** de todo: la base queda como estaba.
> - **[P] psql (lo corre el usuario)**: `psql -h localhost -p <PORT> -U postgres -d taller_mecanico` — la contraseña se ingresa en el prompt o sale de `PGPASSWORD` ya exportada en la sesión del usuario; jamás `-W<clave>` ni `postgresql://...:<clave>@`.
>
> **Governance CRÍTICO**: ante cualquier duda sobre el esquema, borrar la base, o tocar `alembic.ini`/`requirements.txt`, **parar y consultar al usuario**. Dueños sugeridos: A (grupos 1, 2, 7–10), B (3), C (4, 5), D (6).
